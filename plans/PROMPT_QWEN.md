## Интеграция с существующим backend

Backend уже работает на `http://localhost:3000` и НЕ подлежит изменениям.
Твой фронтенд должен работать с ним как есть.

**Требования к интеграции:**

1. **Порт разработки:** зафиксируй в конфигурации сборщика порт **`5175`**
   (чтобы избежать конфликтов при параллельном сравнении реализаций).

2. **Проксирование запросов:** настрой прокси в конфигурации сборщика,
   чтобы запросы к `/api/*` и WebSocket `/ws/*` прозрачно перенаправлялись
   на `http://localhost:3000`. Это избавит от проблем с CORS
   и упростит работу с относительными путями.

   Пример для `vite.config.ts`:
   ```typescript
   server: {
     port: 5175,
     proxy: {
       '/api': { target: 'http://localhost:3000' },
       '/ws':  { target: 'ws://localhost:3000', ws: true },
     },
   }
   ```

3. **WebSocket:** подключение к `/ws/ai-helper` должно работать через прокси
   (тот же хост, что и у фронтенда).

4. **Заголовки изоляции:** для работы `SharedArrayBuffer` (нужен `@ricky0123/vad-web`)
   настрой их отдачу через конфигурацию dev-сервера:
   - `Cross-Origin-Opener-Policy: same-origin`
   - `Cross-Origin-Embedder-Policy: credentialless`

   Для Vite это делается через `server.headers` или плагин.

## Технические особенности @ricky0123/vad-web (критично!)

Эти нюансы выявлены экспериментально и сэкономят часы отладки.
Они касаются функционального блока **F8 (AI Helper)**.

1. **Версия:** использовать `@ricky0123/vad-web@0.0.30` через npm.
   Внутри её бандла встроен `onnxruntime-web@1.22.0`.

2. **Класс `AudioNodeVAD` НЕ СУЩЕСТВУЕТ** в версии 0.0.30.
   Для захвата системного звука использовать второй экземпляр `MicVAD`
   с переопределённой функцией `getStream`:
   ```typescript
   const systemVad = await vad.MicVAD.new({
       ...vadOptions,
       getStream: async () => sysOnlyStream,  // стрим из getDisplayMedia
       onSpeechEnd: (audio) => sendAudioChunk('interlocutor', audio)
   });
   ```

3. **Параметры задаются в МИЛЛИСЕКУНДАХ** (не в кадрах!):
   - `redemptionMs: 800` — пауза для завершения сегмента
   - `preSpeechPadMs: 300` — буфер перед речью
   - `minSpeechMs: 300` — минимальная длительность сегмента

4. **Порядок запросов:** сначала `getDisplayMedia` (системный звук),
   потом `getUserMedia` (микрофон). При отказе от шаринга экрана
   микрофон не должен запрашиваться.

5. **Кодирование аудио в base64:** использовать пакетное преобразование
   чанками по 32 КБ для избежания `Maximum call stack size exceeded`:
   ```typescript
   const chunkSize = 0x8000;
   for (let i = 0; i < bytes.length; i += chunkSize) {
       binary += String.fromCharCode.apply(null, bytes.subarray(i, i + chunkSize));
   }
   ```

6. **Модель по умолчанию:** `silero_vad_v5.onnx` (параметр `model: "v5"`).
   Legacy-модель `silero_vad_legacy.onnx` — резервная.

7. **Однопоточный режим** рекомендуется для стабильности:
   ```typescript
   ortConfig: (ort) => {
       ort.env.wasm.numThreads = 1;
       ort.env.wasm.simd = true;
   }
   ```

## Требования к UI/UX

### Свобода размещения (КЛЮЧЕВОЙ МОМЕНТ)

Ты сам решаешь, **как** организовать интерфейс: количество панелей, их расположение,
пропорции, навигационные паттерны. Ограничений по количеству колонок НЕТ.

**Однако размещение должно соответствовать принципам:**

1. **Частота использования → доступность.**
   То, чем пользуются часто, должно быть в 1 клик.
   Пример: смена модели — быстрый dropdown, а не модалка с тремя шагами.

2. **Контекстная близость.**
   Связанные действия располагаются рядом.
   Пример: выбор модели рядом с полем ввода или отправкой сообщения.

3. **Чат — главный герой.**
   Область диалога должна занимать достаточно места для комфортного чтения
   длинных ответов с кодом.

4. **Прогрессивное раскрытие.**
   Редко используемое (детальная статистика, настройки контекста) —
   скрывается до запроса, не перегружая основной экран.

5. **Предсказуемость.**
   Пользователь должен всегда понимать, где он, что произойдёт при действии,
   и как вернуться назад.
