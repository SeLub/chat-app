## 0. Принятые решения (сводка)

| Пункт | Решение |
|---|---|

## 1. Backend

### 1.1. Схема БД — `src/db/init.js`

**Новая таблица `prompts`** (в `initializeSchema`, до сидов):

```sql
CREATE TABLE IF NOT EXISTS prompts (
    id          TEXT PRIMARY KEY,
    name        TEXT NOT NULL,
    type        TEXT NOT NULL CHECK (type IN ('system', 'user_template')),
    content     TEXT NOT NULL,
    is_default  INTEGER DEFAULT 0,
    created_at  TEXT DEFAULT (datetime('now')),
    updated_at  TEXT DEFAULT (datetime('now'))
);
CREATE INDEX IF NOT EXISTS idx_prompts_type ON prompts(type, created_at);
```

**Изменения `messages`:**
- Новая колонка `sysprompt_id TEXT REFERENCES prompts(id) ON DELETE SET NULL`.
- `ensureColumns`: guarded ALTER для legacy-БД (свежая схема получает колонку из CREATE).

**Изменения `sessions`:**
- Колонка `sysprompt` **удаляется**. В `initializeSchema` её больше нет. В `ensureColumns` — guarded `DROP COLUMN sysprompt` (SQLite ≥ 3.35; иначе `console.warn` и колонка остаётся неиспользуемой — код её не читает).
- **Никаких миграций legacy-значений** (решение P2).

**Сиды** — новый файл `src/db/promptSeeds.js`:

### 1.3. `src/controllers/promptController.js` (новый)

Валидация на входе (на усмотрение P8, минимально необходимая):
- `name`: non-empty после trim, max 200 символов.
- `content`: non-empty, max 100_000 символов.

Хэндлеры:

| Метод | Путь | Body | Ответ |
|---|---|---|---|
| GET | `/api/prompts` | — | `{ prompts: [...] }` (все, `ORDER BY type, created_at`) |

### 1.6. `contextBuilder.js` — сборка `[Инструкции]` и fallback system

**Изменение сигнатуры `buildLLMContext`:**
```js
export async function buildLLMContext(
  sessionId, currentAttachments = [], contextSize = 65536, retainPercent = 80,
  includeQuestionIds = null, mode = 'research',
  promptSelection = {}   // { syspromptId?: string|null, selectedTemplateIds?: string[] }
)
```

**Логика system (P2):**
```js
let sysprompt;
if (promptSelection.syspromptId) {
  const row = promptRepo.getPromptById(promptSelection.syspromptId);
  sysprompt = row?.content?.trim() || DEFAULT_SYSPROMPT;
} else {
  sysprompt = DEFAULT_SYSPROMPT;
}
```
`sessions.sysprompt` больше не читается (колонка удалена).

**Сборка `[Инструкции]` (P1, P5):**
```js
let templatesContext = '';
if (Array.isArray(promptSelection.selectedTemplateIds) && promptSelection.selectedTemplateIds.length > 0) {
  const rows = promptRepo.getPromptsByIds(promptSelection.selectedTemplateIds);
  const ordered = rows
    .filter(r => r.type === 'user_template')
    .sort((a, b) => (a.created_at < b.created_at ? -1 : a.created_at > b.created_at ? 1 : 0));
  if (ordered.length > 0) {
    templatesContext = ordered
      .map(r => `--- TEMPLATE: ${r.name} ---\n${r.content}\n\n`)
      .join('');
  }
}
```

**Финальный `conversation` (порядок — по архитектуре one-system, совместимо с `buildLLMContext`):**
1. `system` (sysprompt)
2. `user [Материалы]` — если `filesContext`
3. `user [Инструкции]` — если `templatesContext` (**новый блок**, после `[Материалы]`, до `[Ранее]`)
4. `user [Ранее в этой сессии]` + история — если `truncatedHistory`
5. `[Вопрос]` добавляется в `chatController` после этой функции

**Почему `[Инструкции]` — user-сообщение, а не часть system:** шаблон Qwen3.8 отвергает второй system («System message must be at the beginning»). Тот же паттерн, что `[Материалы]` и `[Ранее]`.

**`fixedChars`** включает `sysprompt.length + filesContext.length + templatesContext.length`.

**`info`** — добавить `syspromptId: promptSelection.syspromptId ?? null`, `templateCount: ordered.length`.

**`sessionService.buildContext`** — проксирует `promptSelection` параметром.

### 2.6. Поведение чекбоксов (P7)

**Семантика (финальная):**
- Чекбокс = «этот шаблон сейчас вставлен в composer».
- `toggleTemplate(id)`:
  1. Обновляет `selectedTemplateIds` (add/remove).
  2. **Вставка:** если добавляем — `setInputValue(prev => prev ? prev + '\n\n' + template.content : template.content)`.
  3. **Удаление:** если убираем — `setInputValue(prev => prev.replace(template.content, '').replace(/\n{3,}/g, '\n\n').trimEnd())` (удалить **первое** вхождение; если пользователь редактировал текст шаблона — вхождение не найдётся, ничего не ломается — просто чекбокс снимется).
- **Persist чекбоксов в localStorage** (как у сообщения), см. 2.2.
- **F5:** чекбоксы восстанавливаются из `selectedTemplateIds`; текст в composer — из отдельного persist-ключа composer (или сбрасывается — **уточнение P8**: если composer персистится в проекте, оставить как есть; если нет — после F5 чекбоксы «включены», но текста шаблона в composer нет → **рассинхронизация**, см. ниже).
- **Разрешение рассинхронизации (важно):** после F5, если чекбокс `checked`, но `template.content` не найден в `inputValue` — **не снимать чекбокс автоматически** (пользователь мог отредактировать); но в момент отправки **решение принимает сервер**: `selectedTemplateIds` уходят отдельно от composer, `[Инструкции]` собираются из БД (не из composer). Это **согласовано с Моделью A**: composer и `selectedTemplateIds` — независимые каналы. Чекбокс отражает «шаблон включён в промпт», composer — «пользователь дополнительно вставил текст для редактирования». Дублирования в промпте не будет: шаблон попадёт один раз — через `[Инструкции]` (из БД).

> ⚠️ **Это ключевое уточнение Модели A.** Вставка текста в composer — это UX-удобство (пользователь видит и правит), но **источник истины для `[Инструкции]` — `selectedTemplateIds` + БД**, а не composer. Если пользователь правит текст в composer — это идёт в `[Вопрос]` как его дополнение, а `[Инструкции]` содержат оригинал из БД. Это устраняет рассинхронизацию и делает поведение предсказуемым. В ТЗ фиксируем явно.

## 3. Тестирование (критерии приёмки)

### 3.1. Backend
1. `promptRepo`: CRUD, `deletePrompt` с `is_default=1` → throw; `getAllPrompts` сортировка.
2. `initializeSchema`: после init в БД 4 сида (3 system + 1 template); повторный init не дублирует (`ON CONFLICT DO NOTHING`).
3. `DELETE /api/prompts/:id` дефолта → 400 `{ error: 'Cannot delete default prompt' }`.
4. `POST /api/prompts` с пустым `name` / `content` / невалидным `type` → 400.
5. `buildLLMContext` с `syspromptId` → system = `prompts.content`; без `syspromptId` → `DEFAULT_SYSPROMPT`.
6. `buildLLMContext` с `selectedTemplateIds=[t1,t2]` → между `[Материалы]` и `[Ранее]` есть `user` с `[Инструкции]\n--- TEMPLATE: <name> ---\n<content>...` в порядке `created_at ASC`.
7. `chatController`: `syspromptId='nonexistent'` → 400 `invalid_sysprompt_id`.
8. `messages.sysprompt_id` заполняется на user-сообщении и NULL на assistant.
9. Удаление промпта, использованного в messages → `sysprompt_id` становится NULL (FK SET NULL), сообщения целы.
10. Удаление `sessions.sysprompt` из схемы: старый код `SELECT sysprompt FROM sessions` больше не падает (поле удалено).

### 3.2. Frontend
1. `Prompt Manager` открывает `/templatemanager`, список сгруппирован System/User Templates, стат-карточки и поиск — как в Dashboard.
2. Создание/редактирование промпта через модалку; `is_default` — `Delete` disabled.
3. Radio system: выбор сохраняется в `localStorage`; после F5 — восстановлен.
4. Checkbox user_templates: клик добавляет текст в конец composer, повторный клик — удаляет; состояние в `localStorage`; после F5 — чекбоксы восстановлены.
5. `Selected Prompts` модалка показывает system + templates + `[Вопрос]`, обновляется на лету при изменении radio/checkbox/ввода.
6. Отправка: в `FormData` уходят `syspromptId` и `selectedTemplateIds`; ответ LLM соответствует выбранному system (проверить на разном поведении промптов).
7. AI Helper модалка: ширина ~80% на большом экране, resize работает, drag работает, `Minimize` работает.

## 6. Открытые вопросы (финальные уточнения, не блокирующие)

1. **Retain-слайдер** — оставляем во вкладке Questions (он про контекст, не про промпты). Если ТЗ требует его удаления — уточнить.
2. **Composer persist** — если в проекте composer не персистится, после F5 текст в composer пропадёт, но чекбоксы останутся (рассинхронизация визуальная, но **не влияет на промпт** — `[Инструкции]` из БД). Если composer персистится — рассинхронизации нет. Решение: **не персистить composer** (текущее поведение), зафиксировать в WORKLOG.
3. **Дубликаты имён** — не уникальны, разрешены (пользователь может хотеть две версии). В UI предупреждение не показываем (P8).
4. **`is_default` при update** — через PUT не меняется. Если понадобится — отдельная задача.
5. **Selected Prompts modal: `[Вопрос]`** — показывать плейсхолдер `[Вопрос]` + текст composer, если он непуст. Если пуст — просто `[Вопрос]`.
6. **Сиды — точные тексты** — вынести в `promptSeeds.js` (см. 1.1), владелец может скорректировать контент в файле без миграций.
